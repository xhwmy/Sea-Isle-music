# 海屿音乐 · SeaShelf

连接自己的 [Navidrome](https://github.com/navidrome/navidrome) 音乐库的 Android 客户端。原创的深色音乐界面，支持 Android 8.0 及以上。

## 功能

- 浏览专辑、搜索歌手/专辑/歌曲，完整加载分页结果。
- 前台、后台、锁屏播放，以及耳机拔出暂停和音频焦点管理。
- 顺序、列表循环、单曲循环、随机和单曲播放；编辑队列、下一首播放。
- 记住账号对应的队列、模式和进度，重新打开后按播放继续。
- 显示 Navidrome 返回的歌词，支持逐句高亮、自动滚动和点句定位；音乐库需有内嵌歌词或对应的 `.lrc` 文件。
- 可拖动的悬浮播放器，跨应用显示同步歌词和上一首、播放/暂停、下一首控制。
- 在播放页调整手机媒体音量，支持默认关闭的轻度音量增强。
- 手机流量 96 kbps、普通 Wi-Fi 192 kbps 的 MP3 流媒体；播放中缓存当前歌曲、预取下一首，并在临时断线时自动重连。
- 不包含广告、会员促销或广告 SDK。

## 连接自己的音乐库

1. 在电脑安装并运行 Navidrome，配置音乐目录和 FFmpeg；创建自己的用户。
2. 手机和电脑在同一局域网时，填写电脑的局域网地址，例如 `http://192.168.1.10:4533`。`127.0.0.1` 指手机自身。
3. 使用移动网络时，填写已配置的公网 HTTPS 地址，再输入 Navidrome 用户名和密码。不要将不带 HTTPS 的 4533 端口直接映射到公网。

电脑需要持续运行、联网、不休眠。手机只安装本应用即可使用公网 HTTPS 入口；仓库本身不提供服务器、音乐资源或公共账号。可以在电脑配置 Tailscale Funnel 等 HTTPS 入口，服务可用性和传输速度也取决于该入口及电脑上行网络。

登录信息经 Android Keystore 加密后保存在应用私有目录。歌曲流地址包含临时认证信息，不应粘贴到日志或公开分享。切换服务器可使用首页“设置”。覆盖安装时保留原有登录和播放会话。

## 悬浮播放器与动态歌词（0.4.0）

先选择一首歌曲，在播放页的详情区域点击 **“悬浮歌词”**。首次使用按提示打开 Android 的“显示在其他应用上层”权限，再返回应用。权限未授予时普通播放照常可用。

- 拖动标题移动窗口，点击标题返回完整播放页；窗口记住位置并限制在屏幕范围内。
- 悬浮窗提供上一首、播放/暂停、下一首及当前/下一句歌词。点击关闭仅关闭窗口，音乐继续播放。
- 锁屏或熄屏时隐藏窗口；解锁后恢复之前开启的窗口。应用不会开机自动打开悬浮窗。
- 主播放页按真实时间轴逐句高亮并滚动；点歌词可定位到该句，手动滚动后暂停自动跟随约 6 秒。
- 歌词按歌曲和账号隔离，切歌后旧请求不能覆盖新歌词。缺词或获取失败不影响听歌；电脑补词后可点击 **“重新读取歌词”**。

只有带真实时间轴的歌词才同步滚动；无时间轴的文本显示为静态歌词。当前实现为**逐句同步**，不生成虚假的逐字卡拉 OK 时间轴。

### 给电脑音乐库补词

在音频旁放置同名 UTF-8 `.lrc`，例如 `Song.flac` 对应 `Song.lrc`，然后在 Navidrome 执行完整扫描。客户端通过 Navidrome 读取歌词，无须把歌词单独传到手机。

`scripts/import_lrclib_lyrics.py` 可从 [LRCLIB](https://lrclib.net/docs) 补充缺失的同步歌词，默认仅预览：

```powershell
python scripts/import_lrclib_lyrics.py --database "C:/path/to/navidrome.db"
python scripts/import_lrclib_lyrics.py --database "C:/path/to/navidrome.db" --apply
```

脚本以只读方式读取歌曲元数据，核对歌名、歌手、版本与时长，优先同专辑；冲突结果、纯文本歌词和无法可靠匹配的结果均跳过。只创建缺失的同名 LRC，保留已有歌词和原音频。网络请求只发送歌曲元数据；下载内容、缓存与报告默认留在被 Git 忽略的 `.qa/`。歌词源可能缺词或繁忙，失败会单独报告，不等同于没有歌词。

本次本地导入新增 24 份 LRC（缓存转换 13 份、在线匹配 11 份），145 首可用歌曲现有 83 份同名 LRC；其余未取得可靠匹配，另有一首缺少有效时长而跳过在线匹配。正式 Navidrome 完整扫描完成；隔离实例验证了新导入 LRC 可通过 `getLyricsBySongId` 返回同步歌词。

0.4.0 验证：70 项 Android 主机单元测试、13 项 Python 导入测试通过；Android Lint 无错误（5 项既有警告），发布包和设备测试包构建成功，签名与 0.3.2 一致。手机未连接，**设备测试尚未执行**；悬浮窗授权、触控、系统限制与锁屏恢复仍需真机验收。

## 音量调节（0.3.2）

播放页右上角点击“音量”：

- **媒体音量**：调整手机的音乐音量，显示系统实际接受的音量；与手机音量键保持同步。系统限制或固定音量设备会如实提示。
- **音量增强**：默认关闭，可选 0–6 dB，用于录音本身较小的歌曲。增强设置会记住，切歌后仍有效；只作用于本应用的播放会话。增益过大可能失真，可以调低或关闭。

播放页的实体音量键也控制媒体音量。应用不会在打开页面时自动提高手机音量，也不会自动打开增强。音量增强依赖设备提供的音效支持；不支持时保留普通播放并提示，实际响度受手机、耳机与系统音量限制。

手机未连接时无法验证外放/耳机实际效果，也无法代替用户安装；请使用相同签名的新版 APK 覆盖升级。

0.3.2 验证：61 项单元测试全部通过，Android Lint 无错误（5 项既有警告），发布包及设备测试包均构建成功。发布签名与 0.3.1 一致。音量上限、耳机路由和实际听感尚未在手机验证。

## 缓冲与缓存（0.4.3）

播放器使用 AndroidX Media3 ExoPlayer，设置起播、再次缓冲和提前读取阈值；这些是缓冲策略，不代表手机实测起播时间。音频缓存限制为 256 MiB，空间不足时淘汰较早使用的数据。系统也可能回收缓存，因此它不是离线下载功能。

0.4.1 在计费网络（通常是手机流量）请求 96 kbps MP3，普通 Wi-Fi 保留 192 kbps；两种音质使用不同缓存标识，避免复用错误音频。这个选择降低了流量和持续播放所需的网速，但手机流量音质会下降，外网持续速度不足 96 kbps 时仍可能缓冲。

0.4.2 将当前歌曲的滚动预读目标提高到 90 秒，上限 180 秒；起播至少缓冲 3 秒，再次缓冲至少等待 8 秒。播放器会随播放进度继续下载并复用已收到的片段。短暂断线或网关临时错误会从当前进度自动重连，采用 1、2、5、10 秒退避，连续稳定播放 30 秒后恢复重连次数；认证失败等非临时错误不会反复重试。网速持续低于音频码率或电脑/公网入口长期离线时，仍会耗尽缓冲并提示手动重试。

0.4.3 将当前歌曲的预读目标提高到 8 分钟、上限 10 分钟，常见长度的歌曲可在播放中完整进入手机的 256 MiB 私有缓存；再次缓冲的恢复阈值降为 3 秒。当前歌曲接近完整缓冲后，客户端在独立后台任务中预取队列下一首，避免两首歌同时争抢手机网络。随机播放会预先确定下一首，以免下载了错误的歌曲；暂停、切歌、编辑队列和退出时取消过时任务。预取失败不会中断当前播放，至少 60 秒后才重试。Android 缓存仍可能被系统清理，不是永久离线下载。

0.4.3 验证：83 项主机单元测试和 Android Lint 通过；发布 APK 与设备测试 APK 构建成功，发布签名与 0.4.2 相同。设备暂未连接，预取缓存的 Android 集成测试和手机流量实际播放仍需真机验证。

Navidrome 首次将 FLAC 等文件实时转成 MP3 时，输出可能不支持断点续传；已完成的服务端转码缓存支持按字节续传。若有足够磁盘空间，可在 `navidrome.toml` 设置 `TranscodingCacheSize = "1GB"`，重启服务后检查启动日志出现 `maxSize="1.0 GB"`。这主要改善重复播放；首次播放依赖手机端预读和实际网络速度。

缓存按服务器、账号、歌曲和音质隔离，认证链接改变仍能复用相同歌曲的数据。普通网络超时和认证失败不再自动切换为更大的原始无损文件。播放音质为有损转码，电脑原音乐不变。

首次转码流没有时长时，读取错误由应用按当前进度重新连接，避免被播放器当作直播而从头重播；自动尝试次数耗尽后显示“重试”。没有索引的 MP3 定位可能是近似位置。

本机隔离测试：一首 26,554,001 字节 FLAC 转为 4,918,715 字节 MP3，服务器首段返回约 79 ms；整首解码和已完成转码的 Range 读取正常。这是电脑本机数据，**不是手机流量测速**。

0.3.1 构建验证：51 项主机单元测试全部通过，Android Lint 无错误（5 项既有警告），发布 APK 和设备测试 APK 均已构建。设备集成测试已编译，尚未在手机上执行。

## 本地构建

需要 JDK 17、Android SDK Platform 34、Build Tools 34.0.0。项目包含 Gradle 8.2.1 Wrapper，首次构建会下载依赖。

创建自己的 `local.properties`，填写 SDK 路径；该文件不提交：

```properties
sdk.dir=C:/Users/YOUR_NAME/AppData/Local/Android/Sdk
```

Windows PowerShell：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

macOS / Linux：

```sh
chmod +x gradlew
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

调试 APK 在 `app/build/outputs/apk/debug/app-debug.apk`。它使用本机调试签名，**不能覆盖另一签名的已安装应用**。

### 发布签名

用 Android Studio 或 JDK `keytool` 创建自己的密钥库，将其保存为 `.signing/release.jks`，别名 `seashelf`。创建 `.signing/credentials.properties`：

```properties
storePassword=YOUR_KEYSTORE_PASSWORD
keyPassword=YOUR_KEY_PASSWORD
```

执行 `./gradlew :app:assembleRelease`（Windows 使用 `.\gradlew.bat`）。输出为 `app/build/outputs/apk/release/app-release.apk`。务必单独备份签名文件；以后覆盖升级必须使用相同签名。

`.signing/`、`local.properties`、APK、构建输出、音乐、数据库和 `.qa/` 私有测试数据不上传。仓库不附带作者的签名密钥、登录信息或个人服务器地址。

## 验证与辅助脚本

- `:app:testDebugUnitTest`：API 分页、队列、用户意图、会话隔离、凭据加密和缓存策略的主机单元测试。
- `:app:lintDebug`：Android 静态检查。
- `:app:connectedDebugAndroidTest`：需要 Android 设备；缓存复用与 Android 兼容性验证。
- `scripts/test-transcoding.py`：使用独立的临时 Navidrome 实例检查 FFmpeg、完整解码和 Range；不修改正式服务。
- `scripts/test-lyrics.py`：使用独立的临时 Navidrome 实例检查同名 LRC 经真实接口返回同步歌词；临时账号只在该实例使用。
- `scripts/import_kugou_lyrics.py`：本地歌词匹配工具，默认只显示统计，`--apply` 才写入；已有 `.lrc` 不覆盖。
- `scripts/import_lrclib_lyrics.py`：严格匹配在线同步歌词，默认只预览，`--apply` 才写入；源服务失败与匹配失败分别报告。Python 测试可运行 `python -m unittest discover -s scripts -p 'test_import*py'`。
- `scripts/setup-remote.ps1 -CheckOnly`：检查 Windows 端 Navidrome / Tailscale。启用自启动和 Funnel 的脚本依赖现有的目录布局，先阅读脚本并调整为自己的环境。
